# 候補のハッシュ集約

scanは、本文を完全取得し事後検査を通過した候補だけをSHA-256で集約する。同じ完全SHA-256の検出パスは一つの候補グループになり、最初に保持したパスを代表とする。ハッシュがない名前候補、取得途中の本文、パス、サイズ、mtimeでは集約しない。

## 数と属性

- `summary.candidate_count`: 探索範囲で検出したパス数。集約前の数。
- `summary.group_count`: 観測した候補を上記規則で集約したグループ数。
- `summary.retained_group_count`: 出力へ保持できたグループ数。
- `copy_count`: その完全ハッシュで観測した検出パス数。コピー全体に存在する総数の推定ではない。
- `representative_path`、`size_bytes`、`mtime`、本文状態は最初に保持した候補の値。パスと属性の全件ソートは行わない。
- `rule_ids`と`reasons`は同じグループで観測した値の重複なし和集合。最初に観測した順を保つ。いずれかに内容ルール一致があれば`detection_basis=content_pattern`とする。

`paths`は保持できた検出パスを観測順で示す。代表パスを先頭に含む。FSの列挙順が変われば代表や順序も変わり得る。同一本文でも候補ルールに一致しなかったパスは候補数・コピー数へ含めない。

## 上限と切り詰め

候補パスは全グループ合計2,000件かつ元パス2MiBまで保持する。超過後も、既に把握した完全ハッシュの`copy_count`は列挙予算内で数える。個別グループでパスを省略した場合は`paths_truncated=true`、候補詳細を省略した場合は`summary.findings_truncated=true`とする。

JSONのfindings領域は6MiBまでとし、全体8MiBのうち2MiBをroot、エラー、集計、終端へ予約する。必要なら代表以外のパス、続いて末尾のグループを省略し、有効なJSONと代表候補を優先する。`candidate_paths`、`candidate_bytes`、`output_bytes`は到達した上限として`limits`へ記録する。

集約キーも無制限には保持しない。deepの列挙上限200,000件とquickの固定パス3件を合わせた200,003キーを内部上限とし、通常の探索上限内では到達しない。不整合時は保護を緩めず内部異常として停止する。

切り詰めは保持した詳細の限界、`scan_status=incomplete`は探索または結果予算の限界を表す。どちらも未列挙範囲の完全なコピー総数を意味しない。候補0件や一つのグループへの集約は、侵害なし・同じ由来・同じ現在位置の証明ではない。

11の合成評価では200,000候補（2,000同一本文、残り異内容）を処理し、198,001グループを観測しながら候補パス2,000件と出力上限を維持した。[評価結果](ticket11-validation.md)を参照。実データの分布や所要時間の保証ではない。
