# quick探索の契約

05の実装契約。配置根拠は[配置調査](research-note-locations.md)のR1–R5であり、頻度統計ではない。

既定の`scan`と`scan --quick`は同じ探索。すべて固定したコピーroot FDから相対解決する。ホスト側の同名パスを代用しない。06で[内容ルール](content-rules.md)を追加し、一般名・固定案内ファイルも本文取得対象とする。固定案内ファイルの存在を検出理由にしない。

| 順 | 起点 | 範囲・根拠 |
|---|---|---|
| 1 | `.` | 直下のみ。R2のルート配置をLinuxコピーに適用する推論 |
| 2 | `etc/motd`, `tmp/motd`, `tmp/index.html` | 固定ファイルの属性確認。R3のESXi配置事例をLinuxコピーへ適用する推論 |
| 3 | `root`, `home`, `srv`, `var/www`, `var/lib/mysql` | R1/R5と運用上の保存先からの推論 |
| 4 | `tmp`, `var/tmp`, `data`, `backup`, `backups`, `opt` | 補助候補。頻出配置を確認した集合ではない |

ディレクトリ起点は12個。起点自身を深さ0、直下の項目を1とし、通常起点は深さ4まで。深さ4のディレクトリは列挙せず`depth_limit`として方針除外する。ルート直下の起点外ディレクトリは`directory_not_scanned`。`home`も同じ深さ基準で各ホームへ進む。

各起点で一つのディレクトリを最大256項目処理し、上表順で巡回する。各起点の子ディレクトリはFIFO。既に開いた列挙FDを保持し、位置を保持するための再列挙はしない。未開始ディレクトリは元のpin属性と相対パスだけを有限キューへ保持し、開始時の保護付きpinで同一性・版を再照合する。観測した変化は全体停止。

全体20,000列挙項目、起点ごと4,096項目、全体64MiB/起点8MiBの実本文read予算。余りは他起点へ再配分しない。起点予算到達はその起点を不完全として閉じ、後続を継続する。全体予算・期限・安全性異常は全体停止。公平性は処理量の上限と巡回順の保証であり、停止したI/Oや30秒期限内の全起点到達の保証ではない。

待ちディレクトリは全体4,096件かつ相対パス4MiB、パスは4,096バイト未満。超過分を保持せず理由を報告して部分探索を続ける。バッチの名前256件は別に保持するが、キューとの合計も4,096件/4MiBに予約枠を設けて制限する。列挙FDは起点ごと最大1、root/proc4、再取得中pin1、本文FD1を合わせ最大18。結果・エラー・出力の既存予算は維持する。

通常起点の範囲は互いに重ならない。rootで既定起点そのものが現れた場合は別起点で処理し、属性・候補を二重計上しない。固定案内ファイルは直接確認し、`tmp`列挙でも同じパスを再検査しない。列挙項目カウンターは取得した名前の数であり、固定パスの直接照会は含まない。ハードリンク別名は別パスとして数え本文を除外し、同一内容の集約は08の範囲。

未観測の既定パスのENOENT/ENOTDIRは`not_present`、リンク・マウントは方針除外、権限不足は部分探索。列挙済みの子の消失は、既定起点であっても対象変化として停止。明示rootの欠落は従来どおり起動拒否。JSONの`origins`に各起点の範囲・状態・列挙/read量を残し、全体停止時の未完了起点を完了扱いしない。
