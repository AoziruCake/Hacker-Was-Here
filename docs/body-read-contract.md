# 本文取得

scanは探索範囲の通常ファイルを名前・拡張子によらず取得対象とし、[内容ルール](content-rules.md)でも候補を検出する。候補の型・属性を取得したO_PATH FDを閉じず、そのFDから本文を取得する。元パスの通常openへ戻らない。

## 対象と予算

- 通常ファイルnlink=1、サイズは1MiB未満。1MiBちょうど・超過・巨大sparseは本文open前に`file_size_limit`で除外する。EOF確認のため予算外の追加1バイトは読まない。
- 32KiB以下のチャンク、実際に返った本文バイトは合計64MiB以内。後検査で捨てる内容も予算へ計上する。残予算が開始時サイズ以下なら本文openせず`total_read_bytes`で部分探索として停止する。
- 最大1ファイル分の本文を一時保持し、候補の結果には本文を保持しない。05のquickでは本文FDを含む探索所有FDは最大18個。列挙・候補保持・出力等の既存予算も維持する。
- EOFと同一性・サイズ・mtime・ctime・リンク数・マウントの事後検査が成立したときだけ、元バイトの完全SHA-256を返す。途中のハッシュは出さない。予算・キャンセル・readエラー時にも事後検査し、観測した変化・保護条件の喪失は全体停止を優先する。

## テキストと出力

05のquickでは起点ごとの実読取8MiBも適用する。起点の残り予算が開始時サイズ以下なら`content_reason=origin_read_bytes`で本文を開始せず、その起点を部分探索として閉じる。他起点は継続し、全体64MiBは共有する。[quick契約](quick-search.md)を参照。

名前候補は拡張子だけで拒否しない。後続の本文検出向けの分類はUTF-8（ASCIIと先頭BOMを含む）とし、NUL、TAB/CR/LF以外のC0、DELを含まないものを`utf8`とする。不正UTF-8・UTF-16・バイナリは`unsupported_encoding_or_binary`。自動変換や文字コード推測はしない。完全取得できたバイナリにも元バイトのハッシュを付ける。

HTML/HTAは原文データだけとして扱い、実行・レンダリング・リンク先アクセス・展開を行わない。内容判定用データとハッシュは同じFD・読取予算から得る。内容ルールは06で実装した。

JSON v1に以下を追加する。

| 項目 | 意味 |
|---|---|
| `content_status=complete` | EOFと後検査を通過した取得済み本文。内容ルールで検出した意味ではない |
| `content_status=name_only` | 本文未取得。`sha256=null` |
| `content_reason` | 未取得理由。完全取得時はnull。サイズ・ハードリンク・権限・総量・変化・中断・read失敗を区別 |
| `text_status` | 取得後のテキスト分類。未取得時はnull |
| `coverage.read_bytes` | 捨てた読取も含む本文の実読取量。ホストメタデータを含まない |
| `coverage.bodies_read` | EOFと後検査を通過した本文数 |

`scope.content_scanned=true`は内容判定を有効にして探索を開始したことを示す。`excerpt`は常にnull。候補の理由は名前照合と内容一致の固定説明。`detection_basis`で名前のみの一致と内容一致を区別する。08で完全SHA-256が同じ候補を[上限付きで集約](deduplication.md)する。ハッシュのない候補は集約しない。名前の属性が取得済みなら読取失敗時にも名前候補と理由を保持し、失敗した本文・ハッシュは捨てる。

サイズ・ハードリンク除外は方針除外、権限不足はエラーと部分結果、総量・期限は部分結果、観測した変化は終了5、I/Oは6、保護機能喪失・内部異常は4。出力切断は7。詳細は[CLI契約](cli-contract.md)。同期I/Oの強制中断やコピー全体の時点一貫性は保証しない。
