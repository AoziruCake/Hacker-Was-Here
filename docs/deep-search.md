# deep探索の契約

`hwh scan --root ABS --deep`は、quickの優先起点では届かない場所を明示指定で広く調べる。対象rootの事前検査、固定root FD、openat2の経路制約、O_PATHでの保持、本文用FDの再取得、型・属性・マウントの再照合、名前・内容ルール、表示処理はquickと共通である。リンクや別マウントを辿る互換動作はない。

## 範囲と順序

指定rootを深さ0、直下を1として、FIFOで深さ64まで探索する。深さ64の通常ファイルは検査するが、深さ64のディレクトリは列挙せず`depth_limit`として方針除外に記録する。列挙順はFSが返す順序であり、全件を保持・ソートしない。

deepの起点は`.`一つで、JSONの`origins`に`max_depth: 64`と状態・列挙数・本文read量を記録する。quickの15起点や起点別予算はdeepへ適用しない。同じパスを一回だけ訪問し、ハードリンクの別名はquickと同様に別パスとして数えて本文を除外する。

## 初期予算

以下は性能評価前の安全側の初期値であり、対応環境全体での性能保証ではない。

- 列挙項目: 200,000
- 本文の実read総量: 512MiB
- 協調期限: 300秒
- 深さ: 64
- 一回のディレクトリ取得: 256項目
- 待ちパス: 4,096件かつ4MiB（返却バッチ等の予約分を差し引いて運用）
- 一ファイル: 1MiB未満
- 探索用所有FD: 32以内
- 相対パス: 4,096バイト未満
- 候補、エラー、出力: quickと同じ既存上限

待ちパス・パス長・候補等の上限では、その項目を保持せず部分探索を続ける。列挙・本文総量・期限では全体を停止する。上限、権限不足、中断があれば候補0件でも不完全状態として報告する。同期I/Oを期限で強制中断できる保証はない。

## CLI

`--deep`は明示指定だけで有効になる。無指定と`--quick`はquickであり、`--quick --deep`、重複指定、`check --deep`は引数エラーである。deepでも`--root`は必須で、毎回preflightを実行する。`--json`と`--quiet`、終了コード、候補・除外・エラーの意味は[CLI共通契約](cli-contract.md)と同じ。
