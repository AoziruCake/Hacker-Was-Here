# 脅威モデルと安全要件

対象コピーの名前、本文、属性、リンク、特殊ファイル、階層は攻撃者が用意できる入力として扱う。[対応環境と制限](supported-environments.md)を前提とする設計であり、要件の全体が実装済みという意味ではない。実証済みの範囲は[試験結果](ticket01-validation.md)に示す。

## 信頼境界

調査OS、カーネル、実行バイナリ、操作者が準備する対象ルートへの経路と出力先を信頼側とする。対象内の設定・プラグイン・AGENTS.md・文面の指示は実行しない。

「対象の外へアクセスさせない」は、対象から得たパスを使った探索を指定ルート内に制限するという意味である。起動時のランタイム資源や環境確認用のホストprocfsまで含め、プロセスの全OSアクセスが対象内に閉じると約束するものではない。

## 想定する悪用と防御

| 悪用 | 必須の防御 |
|---|---|
| 外部リンクや途中リンクで調査ホストの秘密ファイルへ誘導する | 固定rootFDを起点に、open時の経路制約を維持する。文字列比較や事前検査だけに頼らない |
| 検査後にパスを別ファイル・FIFO・デバイスへ置き換える | O_PATHで保持した実体の型を確認し、自分の保持中FDからだけ再取得。型・dev・inode・mount ID等を再照合してから読む |
| bind mountや複数ハードリンクで対象境界を曖昧にする | NO_XDEVを使い、通常ファイルnlink!=1の本文を除外する |
| 膨大な項目・深い階層・大きな本文で資源を消費する | 本文、列挙、待ち行列、FD、結果・エラー・出力に予算を設ける。未実装の探索予算も公開前の必須条件とする |
| 名前や本文の制御文字で偽の結果を表示する | 攻撃者由来の全表示を引用・エスケープし、長さを制限する。JSONは正規のシリアライザを使う |
| HTMLや要求文の命令を実行させる | データとしてだけ扱い、ブラウザ起動、外部コマンド、対象からの設定読込をしない |
| 途中ハッシュや候補なし表示で結果を誤認させる | EOFと前後確認後だけ完全SHA-256を出す。候補数と探索範囲・未探索理由を別々に示す |

安全な操作が使えない場合は拒否または停止し、元パスの通常openや保護を外した再試行に切り替えない。対象の書換え、削除、実行、外部送信をしない。出力には機密情報が含まれ得るため、保存先とアクセス権は信頼側で管理する。

## 防御の範囲外

侵害済みOS、同等以上の権限を持つ攻撃者、悪意あるカーネルやFSドライバに対する完全防御は提供しない。読み取り専用マウントでも、別経路から更新されないことやコピーの真正性までは証明できない。

担当者が静的なコピーを準備する運用と、ツール内部の安全な読み取りを組み合わせる。動的な変化を観測したら停止するが、観測されなかった変化や全体の時点一貫性を保証しない。ジョークという名称を、防御の省略や安全性の保証の根拠にはしない。

## 検証

[安全なアクセス設計](safe-file-access-design.md)と[受け入れ試験仕様](security-acceptance-tests.md)に従い、無害な合成データを使う。候補の有無だけでなく、対象外canaryのFD取得/read、特殊ファイルの本文open、FD寿命、資源予算、表示を観測する。クロスビルド成功をLinux実機検証の代用にしない。
