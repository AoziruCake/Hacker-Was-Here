# 表示専用ジョークの検証結果

検証日: 2026-10-11。無害な合成コピーを使い、公開`scan` CLIでO05と既存scan回帰を確認した。ジョークは表示層だけの機能であり、安全なファイルアクセス、探索、検出、集約、Reportのスキーマを変更していない。

## 契約と実装

2026-10-11追記: 通常表示の`scan`は既定でdetectiveとfortuneを付ける。`--no-joke`で外す。`--no-hope`は隠し指定のまま追加行だけを足す。`--detective`と`--fortune`はhelp掲載の明示指定で、既定と同じ行になる。`--no-joke`と他のジョーク指定の併用、`check`へのジョーク指定、重複、値付き指定は引数エラー。複数指定時は引数順にかかわらずdetective、fortune、no-hopeの固定順ですべて表示する。各行は`JOKE[...]`と明示し、通常レポートの後へ固定文を加える。対象由来の名前や本文をジョークへ引用せず、乱数や待ち時間も使わない。

探索とReport生成を終えた後にだけジョーク文を組み立てる。JSONとquietでは指定を受理するが表示しない。詳細は[CLI共通契約](cli-contract.md)を参照。

## 検証したこと

- 候補0件の完了、候補ありの完了、部分結果、起動拒否について、全ジョーク指定あり/なしのJSONを時刻以外で比較し、候補、集約、範囲、理由、状態、終了コードが一致した。
- 同じ4状態の通常表示で、3行が`JOKE`と明示され固定順で出ることを確認した。
- 各ジョークとquietの組み合わせで完了時のstdout/stderrが空になり、候補ありの終了コード1が維持されることを確認した。部分結果・拒否・協調中断では必要な固定説明をstderrへ残しつつ、ジョークだけが抑制されることも確認した。
- JSONへジョーク文が混入しないこと、no-hopeがhelpへ出ないこと、detective/fortuneはhelpへ出ることを確認した。
- 重複、値付き指定、`check`への指定が終了コード3と`invalid_arguments`になることを確認した。
- 既存のscan境界・本文・quick/deep・内容判定・集約・途中終了の統合試験も同じイメージで合格した。

## 環境と残る範囲

Linux amd64、Docker管理ボリューム上のext4、非root・capabilitiesなし、ro/nodev/nosuid/noexecの合成コピーで実行した。固定したGo・x/sys・Dockerベースは[読み取り試作の検証結果](ticket01-validation.md)と同じである。試験実行時のネットワークは無効。Linux arm64はクロスビルドだけで、arm64実機、XFS、下限カーネルの実行は12まで未検証である。

ジョーク有無で出力バイト数は変わるため、出力先が途中で切断された場合はいずれも既存契約どおり終了コード7になり得る。停止したI/Oの硬い期限、厳密なRSS上限、全対応環境での最終36ケースはこのチケットの完了範囲ではない。
