# 無害な合成デモの検証結果

検証日: 2026-10-11

## 実装した範囲

実データを持ち込まずに、利用者が`check`、書き込み可能経路の拒否、quick、deep、JSON、除外と不完全状態を順に確認できる使い捨てデモを追加した。Docker管理ボリュームへ合成データを作成し、`ro,nodev,nosuid,noexec`でbind mountした後、hwhを非root・capabilitiesなし・no-new-privileges・ネットワークなしで実行する。

rootで動くのは合成fixtureの作成とmountだけである。hwh本体にコピー取得、mount、展開、権限変更、安全機構を外すオプションは追加していない。結果は信頼側の`test-artifacts/`へ回収し、対象コピー内へ自動保存しない。

公開手順と結果の読み方は[合成デモ](safe-demo.md)を参照する。

## 合成fixture

- quickで見つかる既知名候補
- quickの優先探索外でdeepが見つける既知名候補
- 通常文書
- 外側canaryへのシンボリックリンク
- 名前候補のFIFO
- 複数ハードリンクの名前候補
- 読み取り不能な通常ファイル
- 実行命令に見える文字列を持つ`AGENTS.md`

本物の要求文、秘密、被害データ、マルウェアは使っていない。

## 結果

Linux amd64、WSL2系6.18カーネル、Docker管理ボリューム上のext4で実行した。Go 1.27.2、`golang.org/x/sys` v0.49.0、CGO無効の同じソースからCLIを作成した。

- `check`: 終了0、`scan_status: not_started`、候補なし。安全証明ではない旨を表示
- 同じ内容の書き込み可能経路への`check`: 終了3、`unsupported_mount`。拒否前後でmount optionと読み取り不能ファイルのmodeは不変
- quick: 終了2、候補パス2件、`entry_errors`による不完全状態
- deep: 終了2、候補パス3件。quickで未探索だった深い候補を追加
- シンボリックリンク、FIFO、複数ハードリンクを個別理由で除外
- 読み取り不能ファイルを`permission_denied`として報告
- quickの優先起点外ディレクトリを`directory_not_scanned`として報告
- 通常文書と`AGENTS.md`は候補にしない
- 外側canaryの本文を結果へ取り込まず、`AGENTS.md`の命令文字列による副作用なし
- JSONの候補パス、状態、除外、エラー、列挙数と候補数の分離を自動検証

E06、E08、O04、O06に関係する利用手順を公開CLIで確認した。E10については、`scan`が以前の`check`結果を流用せず、その実行内で条件を再検査する既存実装を使用している。デモは条件を途中変更する故障注入試験の代替ではなく、その境界は既存の統合試験で検証する。

## Q14の結論

デモ提供形態は、固定した試験イメージを使うPowerShell入口と、コンテナ内のPOSIX shell準備・検証処理とする。実データ用のコピー準備は製品機能にせず、信頼できる担当者の責務として文書化する。理由は、取得・mount・権限変更を製品へ統合すると信頼境界と必要権限が拡大し、合成デモ用の特権コンテナを実データ向け隔離環境と誤認させるためである。

実データでは、信頼できるLinux、静的ローカルコピー、ext4、`ro,nodev,nosuid,noexec`、非特権、Linux amd64、読み取り権限、必須Linux機能を条件とする。別パーティションは別rootとして個別実行する。

## 限界

この結果は合成デモの再現性と表示の読み方を確認したもので、実際の侵害コピーの安全な取得・mount、コピーの真正性、侵害判定、復旧、証拠保全を検証したものではない。候補0件を安全確認やエスカレーション不要の根拠にはできない。

arm64実機、XFS、Linux 5.10系は初期対応外である。掲げている範囲の確認は[対応環境横断検証](ticket12-validation.md)を参照する。
