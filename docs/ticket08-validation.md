# 08 ハッシュ集約の検証結果

検証日: 2026-10-10

## 結果

Linux amd64の合成ext4コピーで、完全SHA-256が同じ検出パスだけを一つのグループへ集約することを確認した。同じ名前で本文が異なる候補は別グループ、本文未取得でハッシュがない候補は同じ内容でも個別グループになった。代表は最初の保持パス、理由IDは重複なし和集合、通常表示は代表と`copies`、JSONは保持パス・`copy_count`・切り詰め状態を返した。

2,001件の同一候補では`candidate_count=2001`、`group_count=1`、`copy_count=2001`となり、2,000パスを保持して`paths_truncated=true`と`candidate_paths`上限を報告した。長い相対パス600件では2MiBの`candidate_bytes`、読取不可の長い相対パス70件では256KiBの`error_bytes`を件数上限より先に検出した。異なる本文を持つ長い敵対的名前の候補ではfindings領域を制限し、`output_bytes`を示しながら8MiB以内の有効なJSONを返した。

既存の名前・本文・quick・deep・環境拒否・故障注入・シグナル試験を含む全回帰が合格した。対象外canary、リンク、別マウント、特殊ファイルの本文open/read禁止を独立traceで再確認した。Go単体試験と`go vet`、Linux arm64とWindows amd64のCGO無効クロスビルドも成功した。

## 実施条件

- Go 1.27.2、golang.org/x/sys v0.49.0、CGO無効
- Linux amd64、WSL2系の保守中カーネル
- Docker管理ボリューム上のext4をro,nodev,nosuid,noexecでbind mount
- hwhと監査処理はUID/GID 1000、capabilitiesなし、ネットワークなし
- 合成テキスト、合成リンク、FIFO、デバイスノード、bind mount、tmpfsだけを使用

## 対応した試験

- R08: 大量の同一内容を完全ハッシュで集約し、全パスを無制限に保持しない。
- R04/O03: 候補パス件数・バイト数・JSON出力上限で切り詰めても集計と終端を保持する。
- O01/O02: 制御文字・不正UTF-8を含むパスを安全な表示と有効なJSONで扱う。
- O04: 候補数、グループ数、保持グループ数、探索状態を分離する。
- 回帰: E01–E10、F01–F12、R01–R07の実装済み範囲、O01/O02/O04/O06、quick/deep、内容ルール。

候補のmtime欠落は、必須statx情報の欠落時に候補生成前で停止するため公開CLIの正常候補では作れない。危険な試験用オプションは追加せず、集約単体試験で`null`を別の値に置換しないことを確認した。集約キー上限は探索上限内で到達しない200,003件に固定し、小さい注入上限で到達直前と超過の停止を単体検証した。

## 未検証・保証しない範囲

Linux arm64実機、XFS、Linux 5.10系の実行は未検証で、クロスビルド成功を代用しない。200,000個の異なる集約キー、512MiB本文、300秒期限への実負荷到達と厳密なRSS評価は11の範囲である。

`copy_count`は列挙できた範囲でルールに一致したパス数であり、コピー全体の完全な総数、同じ由来、現在位置、侵害の有無を証明しない。SHA-256がない候補を内容同一と推測しない。出力上限で省略したグループやパスは復元できない。
