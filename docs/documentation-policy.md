# 文書の公開範囲

READMEと`docs/`は、内容を確認した公開候補の文書を置く。リポジトリがprivateの間も、将来の公開を前提に編集する。

| 内容 | 扱い |
|---|---|
| README、使い方、対応環境、制限事項 | 公開候補 |
| 安全設計、脅威モデル、試験方法・結果 | 環境固有情報を除いて公開候補 |
| 会話由来の記録、作業状況、判断履歴 | `.docs/`にローカル保存。必要部分を確認・編集して公開文書へ反映 |
| チケット、下書き | `.scratch/`にローカル保存。初回の公開候補には含めない |
| 作業エージェント向け手順（`AGENTS.md`） | ローカル保存。公開候補に含めない |
| 個人パス、アカウント名、ホスト名、環境識別子、障害復旧記録、生ログ | 公開対象外 |

## 公開文書の確認

1. 公開文書は公開候補の文書だけを参照し、ローカル資料を読む必要がない構成にする。
2. 実装・検証の状況と制限を残し、未検証を検証済みのように要約しない。
3. 試験結果には必要な技術条件（OS系統、CPU、FS、依存版、保護条件）を残す。ユーザー名、ホスト名、実行ごとのID、ローカル生成イメージID、絶対個人パスは除く。正確な環境詳細と生ログは非公開で保存する。
4. 公開する例は合成値を使う。標準APIパスや一般的な入力例を、実際の調査パスやログからコピーしない。
5. Git追加対象とステージ済み差分を個別に確認する。`.gitignore`は補助であり、追跡済みファイルや過去のコミットから情報を消す機能ではない。

`.docs/`と`.scratch/`、`AGENTS.md`、生ログの`test-artifacts/`はGit管理外とする。Git管理外の記録はcloneでは復元できないため、必要に応じて別途アクセス制限した保管先へバックアップする。公開用と非公開用の重複した全文を継続編集せず、公開文書には必要な要件・結論を集約する。

コミット、push、リポジトリの公開設定変更は別の操作として扱う。
