# quick優先探索の検証結果

検証日: 2026-10-10。Linux amd64、WSL2系6.18カーネル、Docker管理ボリュームのext4、ro/nodev/nosuid/noexec、UID/GID1000・capabilitiesなし。Go1.27.2 / x/sys v0.49.0 / CGO無効。合成データだけを使用し、試験実行は無通信。再現方法は[使い方](usage.md)、期待する範囲は[quick契約](quick-search.md)。

## 実装と結果

- 既定scanと`--quick`が同一結果。12ディレクトリ起点と3固定パスをroot FDから解決し、起点別状態・深さ・列挙/read数を端末とJSONへ出力する。
- F01–F03: 再帰先の外部リンク、途中リンク、同じdevのbind mount、別FSを拒否。独立strace監査で対象外pin/read、無保護open、特殊ファイル本文open、通信・追加実行がないことを確認。監査の負の対照も維持。
- F11/F09: 待機中のディレクトリ属性不一致、pin後の実際のディレクトリ移動、再取得失敗、キャンセル、panicをsafefs境界で再現。変化時停止とFD回収を確認。
- R02: 起点8MiBで当該起点を停止して他起点へ進む。全体64MiBでは全体停止し、完全取得済み本文64個（各1MiB−1）だけにハッシュが付く。未取得理由と不完全状態を保持。
- R03/R06: 先行`home`に6,000項目、後続`srv`/`opt`に候補を置き、後続候補が先行起点の4,096項目到達前に発見されることをtraceで確認。各ディレクトリは列挙FDを一度だけ取得し、固定パス・候補の二重処理なし。起動検査時のroot FD再取得は探索列挙とは別。
- R04/O04: 深さ4のファイルを取得し、それより深い階層を除外。多数ディレクトリで待機件数上限、複数起点で全体20,000項目上限を確認。権限不足・起点未存在・方針除外・予算超過を区別。候補0でも上限到達はpartial。
- 既存F01–F12、17ケースのprobe監査、check、scan、E10、本文故障注入、表示・結果保持・出力切断の全回帰が合格。本文故障試験は製品が使うVisitQuick経路へ更新した。
- `go vet ./...`、Linux arm64とWindows amd64のクロスビルド成功。実行試験を代替するものではない。

## 初期資源観測

上記6,000項目の公平性fixtureで、観測した列挙4,101項目、本文6バイト、最大RSS37,268KiB。非trace実行約0.014秒、trace付き約2.211秒、後続`opt`候補の最初のpinは約0.137秒。対象/procを含む観測FDの最大は公平性試験11、再帰境界試験12。構造上の探索所有FD上限は18で、要求上限32以内。

候補は探索終了後に一括出力するため、pin時刻は画面への表示時刻ではない。単一の小さい合成条件の参考値であり、最大RSS・所要時間・検出率の保証ではない。11の大規模合成評価は[別記](ticket11-validation.md)する。

## 未検証・制限

権限不足ディレクトリは、所有者設定後にその所有者でchmodする。全体read上限時は、全起点を開始済みの場合もあり、実行中の起点はincompleteになる。rootの列挙で存在を観測した既定起点が消失した場合は`not_present`とせず、全体停止・当該起点incomplete・後続未開始起点not_startedとする。全回帰は合格した。

現在の起点・深さ4・ext4の名前長では、パス4,096バイトとキュー4MiBの境界は件数・深さ制限より先に到達しない。コードには両方の検査とバッチ用予約を持つが、これらのバイト境界到達は実測済みとしない。

XFS、arm64実機、下限カーネルは未検証。同期I/Oの強制停止や動的コピーの完全な時点一貫性は保証しない。
