## 実施環境

使い捨てのLinux VMで無害な合成データを使う。FSやマウントの準備は試験ハーネス側が行い、hwh本体は非特権で起動する。実サーバー・本物の秘密・実マルウェアは使わない。

初期版の実施対象はLinux amd64とext4である。GoのクロスビルドやWindows単体試験で実機検証を代替しない。arm64実行とXFSは対応外として拒否する。

検証環境の公開要約は[対応環境と制限](supported-environments.md)を参照する。実行ごとの識別情報や生ログは公開文書に含めない。

## 検証する観測値

単に「候補が出なかった」だけでは外部読み取りを防いだ証明にならない。対象外の合成canaryのFD取得／readがないこと、特殊ファイルの本文用openがないこと、予算、FD数、出力状態を観測する。syscall traceまたは試験用監視を併用し、canaryのatimeだけで判定しない。

## 起動時検査

| ID | 条件 | 合格条件 |
|---|---|---|
| E01 | root未指定、相対パス、..、ホスト /、存在しないroot | 列挙・本文読み取り前にinvalid_root等で拒否 |
| E02 | rootと経路途中がシンボリックリンク | 解決せず拒否。リンク先を読まない |
| E03 | UID 0、setuid/setgid状態、capability付き | privileged_executionで拒否。通常の非root bounding setだけでは拒否しない |
| E04 | openat2がENOSYS/EPERM、必要フラグがEINVAL、statx情報が欠落 | unsupported_environment。通常openへのフォールバックがない |
| E05 | procfs欠落、読み取り不能、偽の通常ディレクトリ | 対象本文を読まず拒否 |
| E06 | RWマウント、roだがnodev/nosuid/noexecのいずれかが欠ける | unsupported_mount。hwhがマウント設定や権限を変えない |
| E07 | NFS/SMB/FUSE/overlay/tmpfs/btrfs/XFS等の非対応FS | 明示指定でも拒否。FS検査前のルート経路は信頼側が準備 |
| E08 | ext4上の正しい属性、非root、読めるroot | checkが条件通過を返す。ただし安全の証明とは表示しない |
| E09 | mountinfoが過大、壊れている、ID照合不能、必要属性が矛盾 | 拒否。単なるパス前方一致に切り替えない |
| E10 | check成功後に条件変更してscan | scan独自の再検査で拒否／停止。以前のcheck結果を信用しない |

## ファイルを開く境界

| ID | 条件 | 合格条件 |
|---|---|---|
| F01 | rootの内外に同じ名前の合成要求文 | 内側だけを検出。外側を開かない |
| F02 | 絶対・相対リンク、内部だけを指すリンク、途中のリンク | リンクを追わない。末尾のO_PATH成功時も型検査で除外 |
| F03 | 別FSと同じdevのbind mountをroot配下に置く | 両方をNO_XDEVで遮断。スキップ理由を残す |
| F04 | FIFO、socket、無害な試験デバイスノード | O_PATHでの属性確認まで。本文用open/readをせず、FIFOで待たない |
| F05 | 内部同士・内外のハードリンク | 通常ファイルnlink!=1は内容もハッシュも取得しない。ディレクトリnlinkは誤拒否しない |
| F06 | 読めない通常ファイル | O_PATH成功後も権限を迂回せず、permission_deniedとして記録 |
| F07 | pin後に元のパスをリンク/FIFO/別ファイルへ変更 | 保持中の実体からだけ再取得するか停止。新しい対象を読まない |
| F08 | proc再取得を失敗させる | 元パスの通常openへ切り替えない |
| F09 | FDの開閉を繰り返す、キャンセル・エラー・panic経路 | 生存中のpin FDが再利用されず、FDリーク・二重closeがない |
| F10 | 再取得後の型/dev/inode/mount IDの不一致を試験用に注入 | 本文readゼロで停止／スキップ |
| F11 | ディレクトリpin後の移動 | 属性で許された保持中の実体だけを扱う。対象の変化を記録し、現在位置の完全保証は主張しない |
| F12 | EAGAINを継続して返す | 同じ制約で最大2回再試行し停止／スキップ。無限ループなし |

差し替え試験は、公開CLIの読み取り専用条件を緩めず、内部safefsの試験を専用VM内の可変フィクスチャで行う。製品に--unsafeを追加しない。

## 内容・列挙・資源

| ID | 条件 | 合格条件 |
|---|---|---|
| R01 | 1MiB境界の前後、巨大sparseファイル | 上限超過を本文読み取り前に除外。途中ハッシュを全体SHAとして出さない |
| R02 | 全体読み取り予算到達 | 追加の本文読み取りを開始せず、部分探索と明示 |
| R03 | 大量の項目を一つのディレクトリへ配置 | 全件読み込みせず、列挙・待ち行列予算内で止まる。RSSと件数を記録 |
| R04 | 深い階層、長いパス、大量の候補・エラー | 個別予算を守り、詳細切り詰めと集計を区別 |
| R05 | 本文読み取り中のサイズ・mtime等の変化 | 全体ハッシュを出さず、静的前提の崩壊として停止 |
| R06 | ディレクトリが多数 | 同時FD上限を守り、各起点が有限予算で処理される |
| R07 | キャンセル、協調期限、出力先の切断 | 読み取りを止め、FDを閉じる。カーネル停止I/Oに硬い期限を保証しない |
| R08 | 同一内容の大量コピー | ハッシュ集約しつつ全パスを無制限保持しない |

## 表示とスキャン状態

| ID | 条件 | 合格条件 |
|---|---|---|
| O01 | 名前・本文・エラーに改行、ESC、双方向制御文字、不正UTF-8 | 表示が引用・エスケープされ、偽の結果行を挿入できない |
| O02 | JSONの文字列に引用符・改行・制御文字 | 正規シリアライザ経由で有効なJSONを返す |
| O03 | 出力予算到達 | 終端・サマリーの領域を予約し、切れたJSONを返さない |
| O04 | 候補0件だが除外・権限不足・上限到達あり | 「安全」と表示せず、候補数とcoverageを別々に提示 |
| O05 | 既定ジョーク/`--no-joke`/JSON | 検出・範囲・終了状態が同一。JSONにジョークが混ざらない |
| O06 | コピー内にAGENTS.mdや設定・実行指示がある | データとしてのみ扱い、プラグインや外部コマンドを実行しない |

## 公開前の条件

E/F/R/Oの必須ケースの結果、環境、版、失敗と修正を記録する。E/Fの境界条件が未検証の環境を「対応済み」としない。統合試験とコードレビューに加え、パス検証・mountinfo解析・表示処理には合成入力によるfuzz試験を行う。検出精度の評価はこの安全性試験と分ける。
